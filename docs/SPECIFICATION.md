# PdfNote 仕様書（docs/SPECIFICATION.md）

最終更新: v0.2 (Phase 2)

## 1. プロジェクト概要

学校の授業で配布されるPDF教材にペンで書き込みを行うための、Windows 11専用ローカルノートアプリ。
機能の多さではなく、次の5点を最優先する。

1. 軽快さ
2. ペン入力の低遅延
3. 安定性
4. ローカル完結（ネットワーク不要・通信なし）
5. 保守性

- 対象ユーザー: 学校の授業でPDF教材を使う学生（低スペックPCユーザーを含む）
- クラウド / アカウント / 同期 / 広告 / テレメトリ: **一切なし**

## 2. 対象ハードウェア（最優先動作環境）

| 項目 | 要件 |
|---|---|
| OS | Windows 11 |
| CPU | Intel N200 |
| GPU | Intel UHD Graphics (内蔵) |
| ディスプレイ | 1920x1080 (FHD) |
| 入力 | ペン対応ディスプレイ / ペンタブレット、マウス、タッチ |

性能目標（N100実機での計測を要とする）:

| 操作 | 目標 |
|---|---|
| 通常閲覧 / パン / ズーム / ペン描画 | 60 FPS |
| PDF再レンダリング | UIスレッドをブロックしない |
| ペン入力→描画反映 | 目安 30ms 以内 |

## 4. 非機能要件

- **ローカル完結**: 通常利用でネットワーク通信を行わない。アップデータも持たない。
- **起動時間**: v0.1では2秒以内を目安（N100実機で確認）。
- **メモリ**: ページキャッシュは上限予算（既定 192MB / 最大6ページ）で管理し、無制限にBitmapを保持しない。
- **安定性**: すべての例外を捕捉し、ユーザーに分かりやすいメッセージを表示して継続動作する。

## 5. アーキテクチャ方針（最重要）

PDFレンダリングと手書き描画は**完全に分離**する。

```
PDF ─▶ PDF Renderer (バックグラウンドスレッド, PDFium)
        ─▶ BGRAピクセル ─▶ GPU Texture (CanvasBitmap)
                                +
                          Ink Layer (v0.2〜)
                                ▼
                          GPU合成 (Win2D / Direct2D)
                                ▼
                              画面
```

禁止事項（性能ルール）:

- UIスレッドでPDFレンダリングを実行しない
- ペン入力をトリガーにPDFを再レンダリングしない
- 毎フレーム巨大Bitmapを生成しない
- 毎フレーム大量のGCを発生させない
- 隣接ページを無条件に高解像度先読みしない
- ストロークごとに同期ディスクI/Oを行わない

## 6. PDFレンダリング仕様

- レンダリングエンジン: **PDFium**（Chromiumで使われる実装。BSD-3-Clause）
- .NETラッパー: **Docnet.Core 2.6.0**（MIT。PDFiumネイティブバイナリ同梱、内部で `DocLib.Lock` により全呼び出しが直列化＝スレッドセーフ）
- レンダリングは**専用バックグラウンドスレッド（優先度 BelowNormal）**で実行する
- リクエストは**最新優先 (latest-wins)**: 新しい描画要求が来た時点で古い要求結果は破棄する
- ページ座標はポイント(pt)基準。レンダリング倍率は **px/pt**（例: 100% = 96dpi = 1.333px/pt）で指定する
- 1フレームあたりの上限ピクセル数: 16M px（約4096x4096）。超える場合は倍率をクランプする
- ページの自然サイズは開ドキュメント時に1回だけ取得する

## 7. ページ管理 / キャッシュ仕様

- **先読みはデフォルトで行わない。** 表示ページのレンダリングを最優先する（将来の設定で有効化可能な設計は許容）
- キャッシュ: **LRU（最大6エントリ / 合計192MB予算）**、キー=ページ番号、値=BGRAピクセルバッファ
- キャッシュヒット時はGPUへの再アップロードのみで表示（UIスレッド数ms）
- キャッシュ超過時はLRU側から破棄（GCに任せる。GPUテクスチャは表示中の1枚のみ保持）
- ズーム中は**既存GPUテクスチャを行列変換で拡大縮小**し、PDFを再レンダリングしない
- ズーム停止後350msで、要求解像度とキャッシュ解像度の比率が15%以上乖離していたらバックグラウンドで再レンダリング

## 8. 入力仕様

| 入力 | 動作 |
|---|---|
| ペン (先端) | 手書き (ツール: ペン/消しゴム) |
| ペン (裏ボタン / バレルボタン) | InputAction を実行 (既定: TemporaryEraser) |
| ペン (裏消しゴム端 IsEraser) | 消しゴム |
| マウス左ドラッグ / タッチ1指 / ペン(Panアクション中) | パン |
| ホイール / ピンチ (2指) | ズーム（ポインタ位置中心） |
| PageUp / PageDown / Home / End | ページ移動 |
| +/- (Ctrl含む) | ズーム |
| Ctrl+O | PDFを開く |
| Ctrl+Z / Ctrl+Y | Undo / Redo |
| Esc | パン/ズーム操作のリセット（フィットに戻す） |
| F9 | FPSオーバーレイ切替 |
| F10 | ツールバー表示切替 |

ペン入力から取得する情報: X/Y (ページpt座標)、Pressure (0..1)、Pointer ID、ポインタ種別 (Pen/Mouse/Touch)、バレルボタン状態、裏消しゴム端 (IsEraser)、pressed/moved/released 各フェーズ。

### 8.1 InputAction (ペンボタン割当)

入力と機能は分離し、ペンボタン → `InputAction` → 機能実行の順で処理する。

| InputAction | 内容 |
|---|---|
| None / Pen / Eraser | 動作なし / ツール一時変更 (押している間) |
| TemporaryEraser | 押している間だけ消しゴム (既定) |
| Highlighter | 一時変更 (v1.0) |
| Undo / Redo | 操作実行 |
| PreviousPage / NextPage | ページ移動 |
| Pan | 押している間パン |
| RightClick / CustomShortcut | 将来拡張 |

ツール状態は「基本ツール + 一時上書き」の状態機械で管理し、設定変更時にInk Layer自体を変更しない。

## 8.2 Ink Model (v0.2)

- 階層: `InkDocument ─ InkPage(PageIndex) └ Stroke[]`
- Stroke: PageIndex、Points、Pressure、Width(pt)、Color、Tool、Timestamp
- `InkPoint` は `readonly struct` (Vector2 + Pressure) — ポイント単位のオブジェクト生成なし
- 座標はページpt座標 → ズーム/パン/再レンダリングに影響されない
- 消しゴムは Stroke 単位消去 (v0.2)。部分消去は将来拡張
- Undo/Redoは Operation 単位 (AddStroke / RemoveStroke)。上限256操作
- ペン入力中は PDF再レンダリング / Bitmap再生成 / ファイルI/O / LINQを一切行わない

## 8.3 Ink Renderer (v0.2)

- 完成ストロークはページ単位の **Ink Texture (CanvasRenderTarget)** に焼く
- 描画中ストロークはセグメント単位で直接描画 (テクスチャへの書き込みはストローク完成時のみ)
- ズーム確定時のみ Ink Texture を再構築 (スケール乖離25%超の場合)
- PDF Texture はペン入力中一切変更されない

## 9. 手書きデータ / 保存仕様（v0.2〜設計、v0.1では実装なし）

- ストローク単位: ページ番号、正規化座標列（ページ寸法に対する0..1）、筆圧、線幅、色、作成日時、ツール種別
- 保存先: PDFと同じフォルダに `<PDF名>.note`（JSON、将来SQLite/バイナリへ移行可能な構造）
- 保存はメモリ更新→バックグラウンドデバウンス保存（ストロークごとの同期I/O禁止）

## 10. UI仕様（v0.1）

ツールバー（上、隠せる）: 開く / 前ページ / 次ページ / ページ番号 / ズーム倍率・+- / FPS切替
コンテンツ: CanvasControl (Win2D) が全領域。背景 #202020。
オーバーレイ: 右下に等幅フォントで FPS / Frame / PDF render / Upload / Memory / Cache を表示（F9）。

## 11. エラー処理仕様

| 状況 | 動作 |
|---|---|
| 壊れたPDF / 読み込み不能 | ダイアログ表示、アプリは継続 |
| パスワード付きPDF | 「パスワードで保護されたPDFには未対応です」を表示（v0.1はパスワード入力非対応） |
| ファイル移動/削除 | ページ切替時に読み込み失敗→メッセージ表示 |
| 保存失敗/容量不足 | v0.3で対応。バックグラウンド保存失敗時は再試行+通知設計 |
| メモリ不足 | キャッシュ予算で予防。OOM時はキャッシュ全消去 |

## 12. セキュリティ / プライバシー

- 外部通信なし、テレメトリなし、ファイルシステムはユーザーが選択したPDFと同名の.noteのみアクセス
- PDFはPDFiumのサンドボックス外プロセスなしでインプロセス描画（クラッシュ時はアプリ単位の影響に留める）
